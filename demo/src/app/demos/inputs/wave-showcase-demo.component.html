Rich text — four-wave showcase

Temporary page. Every section below maps to a shipped change so it can be validated by hand. The permanent demos live on the four rich-text-* routes.

1 · Markdown input rules + block-state toolbar

shortcuts: {{ shortcutsOn() ? 'on' : 'off' }}

Type # , - , 1. , > , [] , ---, **bold** or backtick-code. Each transforms live and is one undo step — press Backspace straight after to revert just the transform. Watch the “Text style” select and the toolbar buttons reflect the caret’s block.

2 · Find & replace v2, undo consistency, dirty state

Press Ctrl/Cmd+F (or Ctrl/Cmd+H). Matches now span inline markup — search quick brown and note the second one is found even though quick is bold. Highlights are an overlay, so they never enter the saved HTML. Whole-word and regex toggles are in the panel.

setContent() markClean() recordExternalWrites: {{ externalWrites() ? 'true' : 'false' }} canUndo {{ history().canUndo }} · canRedo {{ history().canRedo }}

With recordExternalWrites on, the programmatic write above is undoable — press Ctrl+Z after it. Turn it off and undo skips past it.

4 · Reactive-forms validators

These measure visible text, not markup. An empty editor still emits <p><br></p> in HTML mode, which Angular’s own required counts as content — richTextRequired() does not.

5 · ui-rich-text-view — publish what you authored

A read-only renderer sharing the editor’s sanitizer and prose typography, so a document looks identical authored and published. No toolbar, no contenteditable.

6 · Bug fix — control.disable() now reaches the editor

The editor implemented ControlValueAccessor without setDisabledState, so a disabled form control left it fully editable — it was the only form component in the library missing it.
